# 1.9.0 test candidate verification

The current candidate is `1.9.0-rc.2`. This is a local implementation and the authorized gauravtiwari.org test installation, not a stable release. The [generated security report](2026-09-13-security-scan.md) records the audited snapshot before remediation.

## Security fixes

- **High, reserved-path interception:** shared link validation now rejects protected direct paths. Runtime exclusions protect existing direct/regex rules, encoded paths, WordPress subdirectories, script endpoints, and plain-permalink REST routes. Tests include catchall 307 rules against login POSTs. An encoded-path regression caught sanitization stripping percent bytes; the guard now decodes the original parsed request path before matching.
- **Medium, CSV formula injection:** legacy and analytics exports share cell protection. All readers/writers explicitly disable PHP's backslash escape for consistent CSV enclosure semantics. Format 3 decodes protected text during reimport; authenticated HTTP tests verify formula-like names, quote/backslash cells, and lossless roundtrips.
- **Medium, public import staging:** CSV uploads are restricted to real uploaded CSV files within a finite size limit, stored outside public site directories with restricted file/directory permissions and random tokens. Cancellation, invalid mappings, successful imports, and scheduled expiry remove their exact staged files. No broad removal of unknown historical upload files was performed.

The source-only audit found no additional issue in analytics authorization, persisted opt-in, prepared queries or output escaping. This is bounded review evidence, not a guarantee that no other vulnerabilities exist. Workbench remediation records remain tied to the original snapshot; the tests and candidate commit document the fixes.

## Local evidence

The exact ZIP passed 63 integration, 7 timezone, 12 failure-path, 33 security/settings regression, and 12 authenticated HTTP checks on WordPress 7.1, PHP 8.5.10 and a disposable MariaDB database. Timezone checks cover numeric +05:30 (the live site's configuration), named fractional offsets, subsequent timezone changes and both DST transitions.

PHP syntax and WordPress coding standards pass with the pre-existing class-filename rule excluded. The compiled block assets build successfully. Browser checks cover settings saves, never-enabled and paused states, overview navigation, accessible native controls and a 390px viewport without document overflow.

Private local evidence is retained under ignored `build-release/qa/`: `rc2-zip-*.json`, package manifests, source-only audit reviews, benchmark results and guarded live verification records. It contains operational details and is intentionally excluded from the distributed plugin.

## Performance limits

No scripts, cookies, beacon requests or browser storage are added to visitor pages. A cold eligible collector request uses one configuration read and one prepared insert; it makes no table-metadata query. FPM finishes the redirect response before the independent counter and event append. The synchronous fallback must complete database writes before the response ends.

The local FPM stress fixture measured combined counting/analytics p95 worker time of about 3.22ms versus 3.14ms for the old basic counter, with about 8% less throughput under saturation. This small uncached test does **not** establish the proposed 95% throughput acceptance target or a precise sub-millisecond CPU budget. A synthetic 90,000-row report fixture returned correct totals at about 64ms p95. These are local measurements, not production capacity promises.

The minimum/current PHP and WordPress CI matrix is authored but has not run remotely. No production load test was performed. Broader hosting, concurrency and capacity validation remains a stable-release gate.

## Live test

Both the original 1.8.1 installation and the RC1 installation were backed up before replacement. RC2 installed successfully, stayed active, and matched the tested package file hashes. Read-back checks confirmed unchanged original link configuration, unchanged basic settings, and no decrease in existing counters.

A synthetic redirect returned 302 without cookies. Its eligible GET generated one minimized event; HEAD and recognized-bot requests affected only the legacy total. Two prefetch probes received a Cloudflare 503 response without reaching the link counter; production prefetch behavior is therefore unconfirmed through the edge, although local collector tests exclude it correctly.

The existing system scheduler processed the new event automatically and advanced the recurring job. Its report used the site's numeric WordPress timezone (+05:30). Earlier RC1 maintenance had lost its recurring entry; the entry was restored, subsequent recurring runs were observed, and RC2 adds repair in admin/worker contexts only. The original cause of the missing entry was not proven.

The exact temporary test link and its analytics rows were removed. The original catalog hash was restored, all existing counters were preserved, and both opted-in advanced analytics and the existing basic counts remain enabled. Backup artifacts remain available for rollback.
