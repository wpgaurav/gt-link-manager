# GT Link Manager 1.9.0 release verification

The stable release consolidates the RC changelogs into five user-facing entries. Analytics stays separately opted in, uses WordPress time and preserves the original basic counter. The release workflow publishes the same concise changelog on GitHub and deploys the versioned package to WordPress.org.

## Compatibility and behavior

[Plugin checks](https://github.com/wpgaurav/gt-link-manager/actions/runs/34850233636) passed WordPress 6.4 / PHP 8.0 and current WordPress / PHP 8.3 and 8.5 on MySQL 8.0. The initial minimum-version job found a test-harness reflection access difference; explicit reflection access for PHP 8.0 fixed it without changing plugin runtime code.

The exact local release ZIP passed all nine PHP suites on WordPress 7.1 / PHP 8.5 / MariaDB, plus authenticated HTTP CSV import/export and clipboard checks. Prior candidate browser and live upgrade evidence covers the same runtime implementation, with final diagnostics wrapping checked on desktop and mobile. Gatilab's upgrade from 1.8.1 preserved its catalog and counting preferences; both sites' subsequent candidate upgrades preserved settings, generations and reports.

Four concurrent appenders and overlapping maintenance produced the expected total, no pending records and reconciled breakdowns. Source cardinality remained bounded. A 162,000-row, 90-day fixture returned correct overview, page-report and page-list results at approximately 227ms, 64ms and 107ms p95 respectively. EXPLAIN for the full-range total showed a full scan, which is recorded rather than presented as an indexed narrow-range lookup.

## Performance scope

Repeated native FastCGI runs used four PHP workers and three rounds of 2,000 requests per mode, with real referring-page headers and no persistent object cache. There were no redirect errors. Median-of-round p95 TTFB was 3.18ms for 1.8.1 basic counts and 3.76ms for 1.9.0 basic counts plus analytics, a difference of 0.58ms. Visitor pages gain no analytics scripts, cookies, storage or beacon requests. The eligible collector remains a configuration read plus one insert, separate from the basic count.

Saturated throughput was about 86% of the old basic-counter baseline in this local shared-host fixture. The original 95% throughput aspiration was not established, and CPU timing resolution was insufficient for a precise sub-millisecond CPU claim. The release makes no zero-server-cost or universal capacity promise: enabling analytics adds database writes and worker occupancy. Results are local measurements, not production load tests; storage/lag safeguards and configurable retention remain in place.

## Distribution and authorization

The user explicitly authorized releasing 1.9.0. The plugin header, constant, stable tag, description, upgrade notice and translation metadata identify 1.9.0. No RC changelog headings remain in the published readme. Test/audit/development files and local configuration are excluded from the distribution. The source payload matches the local ZIP; published GitHub and WordPress.org payloads are checked separately during release.
