# GT Link Manager 1.9.1 audit (2026-10-04)

Branch `fix/analytics-storage-warning` (from `codex/audit-v1.8.1-plan-v1.9.0`). Four read-only reviews (redirect core and data layer, admin/REST/import/editor, analytics, competitor feature gaps) plus a hands-on UI audit on a seeded local fixture at 1440px and 375px. Findings were checked against the code; reviewer claims that could not be confirmed are marked unverified.

## Incident: "Collection is paused because reports have not updated recently"

- Cause: the analytics tables passed the 100 MB hard stop (108 MB on gauravtiwari.org). The worker flipped to `unhealthy` and the collector dropped every click from 2026-10-02 14:13 UTC. Cron was healthy and lag was 0; the notice blamed stale reports instead of storage.
- Root cause of the size: 19,688 clicks produced 173,278 summary rows (1.23 clicks per row, about 11 rows per click, ~5.4 KB per click). About 40% was InnoDB fragmentation from random-order primary key inserts.
- Fixed in 5e4efbd and deployed: no size or lag stop, a configurable storage warning (default 100 MB) with Delete old data, accurate notices. A compaction with zero rows deleted took production from 108 MB to 64 MB in 4.2 s. Collection resumed at 13:30 UTC.

## Open findings, by priority

### High

1. **Fixed (rollup).** **Analytics privacy promise vs storage.** Summaries are bucketed per UTC minute, and 87.5% of rows hold one click, so a "summary" row set reconstructs an individual click (minute, page, country, device) for 90 days or forever. The privacy text says individual click records are kept for 7 days. Interim fix (M): in maintenance, roll minute rows older than `event_days` into one row per link, dimension, value and local day. Full fix: storage model H below.
2. **Fixed (daily export).** **Analytics CSV export fails on the default 30-day view in production.** The export counts raw minute rows against a 100,000 cap, which the `''` cohort hits after about 14.6 days of data. Export what the report shows (grouped by link, local day, dimension, value) and raise the cap. (M)
3. **Fixed.** **Advanced redirects off converts direct and regex links to standard on any save.** The form hardcodes `link_mode=standard` and drops the replacement and priority fields; geo fields are already preserved with hidden inputs. (S) `class-gt-link-admin-pages.php:124-145`
4. **REST `url` means the branded URL in `GET /links` but the destination elsewhere.** An AI tool that lists then PATCHes back can point a link at itself (redirect loop). Use one response shape and reject destinations that are this site's own prefixed paths. (M) `class-gt-link-rest-api.php:348-409`

### Medium

5. **Standard lookup also matches direct and regex rows, and the alias cache key is never invalidated.** A direct link `black-friday` also answers at `/go/black-friday`; with Redis it keeps redirecting after the direct link is trashed. (S) `class-gt-link-db.php:99`, `569-584`
6. **Percent-encoded slugs are mangled by `sanitize_text_field` on the request path.** `deal-🔥` resolves to a different link `deal`; Hindi slugs miss. (S) `class-gt-link-redirect.php:413,458`
7. **Prefix can collide with core bases.** `page` breaks home pagination, `blog` breaks posts; nothing warns. (S) `class-gt-link-settings.php:188`
8. **Overview runs ~10 queries that each scan the whole date window** because `dimension` follows a range column in both indexes. Change `page_date` to `(page_key, dimension, bucket_start)`: about 10x fewer index reads. (S) `class-gtlm-analytics-db.php:94-95`
9. **Orphan cleanup scans the whole summary table every 5 minutes** when there are no orphans (the normal case). Use `SELECT DISTINCT link_id` in a derived table, or queue deleted IDs. (S, unverified EXPLAIN) `class-gtlm-analytics-db.php:315`
10. **Fixed.** **Bot filter gaps.** Empty or oversized user agents are counted; curl, Wget, python-requests, Go-http-client and similar are not matched. (S) `class-gtlm-analytics-collector.php:34,97`
11. **Block editor inserter** offers inactive and regex links (regex inserts an empty link), fires a request per keystroke, and inserts nothing when no text is selected. `GTLM_DB::search_links()` was written for it but is unused. (S–M)
12. **Bulk "Set category" with no category picked wipes categories**, with no undo; category delete is a one-click GET. (S)
13. **A failed save loses everything typed** and reports only "Save failed". The admin form's validation lists differ from `GTLM_DB::valid_link_definition()`. (M)
14. **Pretty Links import preset** maps only `nofollow` (sponsored becomes nofollow), skips tags, and flattens slugs containing `/`. (M, verify against a real export)

### Low

- Prefix change: the rewrite flush on settings save keeps the old rule; deactivation leaves it. Use `delete_option( 'rewrite_rules' )`.
- `gtlm_settings` is not autoloaded but read on every request; `gtlm_db_version` is autoloaded.
- Trash purge compares local `created` time to a UTC cutoff.
- Regex substitution: `$1` replaced before `$10`; the replacement branch appends the unmatched remainder.
- `gtlm_headers` cannot change cache headers (sent before `nocache_headers()`).
- Uninstall does not flush the cache group or clean all sites on multisite.
- Quick Edit: no focus management, hardcoded English labels, `href="#"` buttons; radio groups lack fieldset/legend.
- Row and bulk actions drop search, filters, sort and page.
- Breakdowns silently cut at 200 values; add an "All other" row.
- Fixed: geo outcome is stored even with countries off and is not in the privacy text.
- The events table `pending` index is redundant with `page_pending`.

## UI audit: remaining recommendations

- Move Reset Clicks to a bulk action; every row then fits 56px.
- Settings: the AI setup prompt sits above the settings people change; Save is mid-page; headings mix Title Case ("Detection Method", "Empty Trash Automatically") with sentence case.
- "Category for bulk action" sits among the filters; move it next to Bulk actions.
- Edit screen: group fields (Destination, Behaviour, Organisation, Advanced), show lifetime clicks with an Analytics link, add Trash.
- Categories: confirm delete and show the link count.

## Storage model (analytics)

Current: 3,409 B per click compacted, 5,646 B as it grows; 293–485 MB per 90 days at 1,000 clicks/day.

Recommended model H: a dictionary table for hosts and page URLs; `q15` (15-minute UTC buckets, time-leading key) for all counts; `daily` (site-local date, time-leading key) for breakdowns only, dropping `total`, `page`, `status` and `mode` rows. About 272 B per click, ~27 MB per 90 days, no fragmentation, no OPTIMIZE needed, and it resolves High #1. Migration: schema 4, cut over by processing time under the control lock, keyset backfill with a crash-safe cursor, verify per-day totals before switching, keep `_hourly_v3` for one release.

## Feature gaps (ranked)

1. Destination health checks (opt-in, separate table, HEAD then GET, "blocked" distinct from "broken").
2. Where-used index: which posts contain each link; warn before trashing or re-slugging a link still in content.
3. Bulk find-and-replace on destinations with preview and Undo (tracking-ID changes, network migrations).
4. Scheduling and expiry: start/end dates, expired fallback URL or 410, checked in the redirect, no cron.
5. Direct importers from Pretty Links, ThirstyAffiliates and BetterLinks data that keep old URLs working.
6. Create a link from the editor popover when search finds nothing.
7. Per-link query parameter forwarding (destination params win).
8. Sub-ID tokens such as `{post_slug}` for per-article network revenue with no cookies.
9. Missing-slug log (opt-in, no IP).
10. WordPress Abilities API registration so MCP clients see GT tools.

Analytics features that fit the no-JS, no-cookie model: clicks per post (Posts column and editor panel), sparklines in the links list, weekly digest via `wp_mail`, spike flags.
