# GT Link Manager 1.9.1 release verification

1.9.1 fixes a production analytics stop, closes a privacy gap in stored analytics, and fixes link-integrity bugs found in the 2026-10-04 audit (`2026-10-04-v1.9.1-audit.md`). The readme changelog is consolidated into seven entries; the release workflow publishes that section as the GitHub release notes.

## What changed

- Analytics never stops collecting for storage size or processing lag. A storage warning level (default 100 MB) prompts Delete old data, which deletes in bounded batches, then compacts once.
- Privacy: summaries keep minute buckets only within the individual-record window (`event_days`, default 7). Older site-local days are rewritten to one row per link, page cohort, dimension and value at local midnight, one idempotent transaction per day, tracked by `rolled_until`. Hourly trends reaching rolled days are grouped by day. CSV export is daily (`time` column renamed `date`).
- Collector: geo-rule outcome recorded only when countries are on; empty, oversized and common scripted user agents are not counted.
- Links: Quick Edit no longer rewrites regex patterns or direct paths; renaming keeps the slug; saving with Advanced redirects off keeps direct and regex modes; failed lookups are not cached; migrations run on the first request after an update.
- Admin: phone layout of the links list, Tabler icons (MIT), Top links destination column, Edit Link title, mtime asset versions.

## Tests

- 293 checks in 12 suites (`tests/run.sh`, including new `storage-warning`, `ui-regressions`, `rollup`) pass on WordPress 7.1.2 / PHP 8.5.10 with both MariaDB 13.0.2 and MySQL 8.0.46 (Docker, the CI engine). `node tests/ai-prompt-copy.mjs` passes. phpcs (WordPress-Extra) is clean.
- PHPCompatibilityWP for PHP 8.0+: clean apart from a pre-existing false positive (`self::family()` read as the removed `fam` extension).
- The rollup suite runs in UTC, Asia/Kolkata and America/New_York across the 2026-03-08 DST change: per-local-day totals unchanged, one stamp per rolled day at local midnight, recent days keep minutes, a day with remaining raw events is not rolled, re-rolling is a no-op, hourly views fall back to daily only for ranges reaching rolled days.
- The storage-warning suite was run against the 1.9.0 code and failed. The ui-regressions and rollup suites target behavior and methods that 1.9.0 lacks; they were not separately run against it.
- Not run locally: the PHP 8.0 / WordPress 6.4 minimum job (CI covers it on push) and redirect throughput benchmarks. The redirect path changed only in cache writes for lookups.

## Production (gauravtiwari.org)

- Incident: analytics passed the 100 MB hard stop and dropped clicks from 2026-10-02 14:13 UTC until the first 1.9.1 build at 2026-10-04 13:30 UTC. A zero-row compaction took storage from 108 MB to 64 MB.
- Before the rollup: tables dumped to `~/gtlm-backups/gtlm-analytics-before-rollup-20261004-201206.sql.gz` and verified (173,507 summary rows, 5,366 events, 1,447 links). A per-local-day fingerprint (group count, clicks, CRC32 of every link/page/dimension/value total, `+05:30`) was taken.
- Rollup: three maintenance runs (2.0–4.7 s each including WordPress boot) rolled 13 Sep to 26 Sep and stopped at the window. Summary rows 173,507 to 132,999.
- Fingerprints for all 21 complete days are identical before and after; only the current day differed, by new live clicks. Each rolled day holds exactly one bucket at 00:00 local.
- Reports: 30- and 90-day totals 15,509 before, 15,512 after (live clicks), same top link. A 30-day hourly request falls back to daily; a 4-day hourly request returns 46 hourly buckets.
- Export: the 30-day all-links export, refused before, completes in 1.19 s (930 links, 81,232 daily rows) and its totals equal the report.
- The release-candidate ZIP below is installed on production; cron maintenance runs with no errors, redirects return 301/302/307, a missing slug returns 404. Plugin backups for every deploy are in `~/gtlm-backups`.
